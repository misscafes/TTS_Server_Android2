豆包的建议是如下修复：
结合你是 Room + 备份恢复场景，分快速临时修复、彻底根治、代码逐行改造三步，按顺序操作即可，附完整可直接复制的代码。
 
一、先做临时修复（Android 11+ 立竿见影，优先操作）
 
适用于安卓11及以上机型，不用改表结构，临时扩大游标内存。
 
1. 打开你的  Application  类
 
在  onCreate()  最开头添加代码：
Kotlin 版本
 
kotlin
  
import android.os.Build
import android.database.sqlite.SQLiteDatabase

override fun onCreate() {
    super.onCreate()

    // 扩大 CursorWindow 大小，解决单行数据过大
    if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.R) {
        // 设置为 10MB，根据实际大小可调整
        SQLiteDatabase.setCursorWindowSize(10 * 1024 * 1024)
    }

    // 原有代码...
}
 
 
Java 版本
 
java

2. 重新运行 App
 
高版本手机基本就能解决崩溃。
 
缺点：Android 10 及以下无效，低版本依旧会崩，必须走下面根治方案。
 
 
 
二、根治方案（推荐，兼容所有安卓版本）
 
核心原因： speech_rule  表某一个字段数据太大（长文本/Base64/二进制），查询  SELECT *  时单行超限。
 
步骤1：定位大字段
 
1. 找到你的 Room 实体类  SpeechRule.kt  /  SpeechRule.java 
2. 观察字段：
- 超长字符串（String）
- 字节数组  ByteArray  /  byte[] （BLOB）
 
这类就是元凶，不要把大文件/大文本存在数据库字段里。
 
步骤2：方案A（最简单：查询时不查大字段）
 
如果备份/恢复逻辑不需要用到这个大字段，直接修改 DAO 查询语句，禁止  SELECT * 。
 
举例改造（Room DAO）
 
原错误代码（大概率是这种）
 
kotlin
  
// SpeechRuleDao.kt
@Query("SELECT * FROM speech_rule")
suspend fun getAllRule(): List<SpeechRule>
 
 
修改后（只查询业务必需字段，排除大字段）
 
假设： bigContent  是超大字段，直接去掉它
 
kotlin
  
// 只写你真正需要的列，不要 *
@Query("SELECT id,name,time FROM speech_rule") 
suspend fun getAllRule(): List<SpeechRuleSimple>
 
 
配套：新建精简实体（只包含查询的字段）
 
kotlin
  
// 精简实体，不包含大字段
data class SpeechRuleSimple(
    val id: Long,
    val name: String,
    val time: String
)
 
 
作用：查询只加载小字段，单行体积变小，不会触发溢出。
 
 
 
步骤3：方案B（必须读取大字段 → 分表存储，终极方案）
 
如果业务必须读取大字段，就把大字段单独拆成一张表。
 
1. 拆分原有实体
 
原实体：
 
kotlin
  
@Entity(tableName = "speech_rule")
data class SpeechRule(
    @PrimaryKey val id: Long,
    val name: String,
    val normalText: String,
    val bigBlob: ByteArray // 超大字段，拆分出去
)
 
 
拆分为主表 + 大字段附表：
 
主表（常规小数据）
 
kotlin
  
@Entity(tableName = "speech_rule_main")
data class SpeechRuleMain(
    @PrimaryKey val id: Long,
    val name: String,
    val normalText: String
)
 
 
附表（只存大字段，一对一关联）
 
kotlin
  
@Entity(tableName = "speech_rule_big_data")
data class SpeechRuleBigData(
    @PrimaryKey val ruleId: Long, // 和主表id关联
    val bigBlob: ByteArray // 仅存放大数据
)
 
 
2. 修改 DAO，分开查询
 
先查主表列表（小数据，安全），再根据 id 按需查询大字段：
 
kotlin
  
// 1. 查询全部常规数据（备份优先查这个，不会崩溃）
@Query("SELECT * FROM speech_rule_main")
suspend fun getAllMainRule(): List<SpeechRuleMain>

// 2. 根据id单独查询单个大字段（按需加载）
@Query("SELECT * FROM speech_rule_big_data WHERE ruleId = :ruleId")
suspend fun getBigDataById(ruleId: Long): SpeechRuleBigData?
 
 
3. 业务逻辑改造（备份/恢复处）
 
原来一次性查全部数据 → 改成先查列表，再逐个加载大字段，避免单行过大。
